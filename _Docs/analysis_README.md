# Анализ данных

Основа: вторая миграция. Ветка: feature/data-analysis.

## Промпт к ИИ (Codex)
Сформируй DML-скрипт PostgreSQL для базы после второй миграции: users, batches, parameters с parameter_type_id и measurement_date, справочники parameter_types и measurement_units. Сохрани исходные измерения. Добавь относительную влажность в процентах как пятый тип параметра. Добавь трех тестовых сотрудников: одному полную пачку из пяти разных параметров, второму четыре параметра с влажностью 120 процентов, третьему пустую пачку. Используй учебные даты и явно обозначь намеренные ошибки. Создай отдельные пять запросов: сравнение числа измерений всех сотрудников с учетом нулей, поиск пустых пачек, проверка пяти разных ожидаемых типов в каждой пачке, поиск NULL и значений вне учебных диапазонов, проверка единиц в справочнике типов. Диапазоны: высота -500..9000 м, температура -90..60 градусов Цельсия, ветер 0..100 м/с, снос 0..1000 м, влажность 0..100 процентов. Это учебные границы, а не нормативы.

Использован Codex; GigaChat/Yandex AI в задании указаны как желательные.

## Запуск
1. На базе после второй миграции выполнить _Infra/analysis_data.sql один раз.
2. Из _Infra/analysis_queries.sql выполнять каждый из пяти SELECT отдельно.
3. Сохранить пять скриншотов в _Docs/analysis/ под именами 01_counts.png, 02_empty.png, 03_completeness.png, 04_ranges.png, 05_units.png.

## Ожидаемые результаты на исходных данных задания
- 5 сотрудников: 3, 3, 5, 4, 0 измерений соответственно; равенства нет.
- Одна новая пустая пачка (Кузнецов).
- Полная пачка Сидорова; исходные пачки содержат по 3 параметра, пачка Смирновой 4, Кузнецова 0.
- Одна ошибка диапазона: влажность 120%.
- Все пять типов имеют правильные единицы.

Данные содержат намеренные дефекты для демонстрации проверок. Скриншоты и фактические результаты добавляются после выполнения в pgAdmin.
